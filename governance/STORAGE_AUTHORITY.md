# Storage and Version Authority

## Google Drive

Root: `The Legacy — Image Generation`

Google Drive is authoritative for:

- canonical visual masters;
- unverified visual intake pending approval;
- independent Laboratory outputs;
- evaluation images and evidence;
- approved production outputs;
- released migration/handoff packets.

Folder roles:

- `00 Control & Resumption` — released control packets usable by fresh workspaces;
- `01 Canonical Masters` — verified and explicitly approved masters only;
- `02 Experiment Packets` — frozen experimental prompts and preregistrations;
- `03 Laboratory Evidence` — generated descendants and run records;
- `04 Evaluation & Dashboard` — classifications, observations, dashboard releases;
- `05 Production Outputs` — useful non-evidentiary descendants and corrected releases;
- `06 Releases & Handoffs` — dated transfer packets and resumable snapshots;
- `90 Archive` — historical or superseded material retained for provenance;
- `99 Unverified Intake` — candidate sources that have not passed human verification.

## GitHub

Target: public repository `Naterad86/the-legacy-image-generation`.

GitHub is authoritative for versioned text controls: instructions, governance, manifest metadata, prompts, rubrics, experiment definitions, dashboard source text, changelog, and handoffs. Public visibility supports collaboration, but the repository must not contain canonical art, raw generations, or duplicate visual evidence.

## ChatGPT

A ChatGPT project is an active execution surface. Its project instructions and Sources must be populated explicitly from the released control packet and verified masters. Chat history, filenames, memories, thumbnails, and generated descendants do not establish source authority.

## No competing duplicates

When the same text appears in Drive and GitHub, GitHub is the editable source and the Drive copy must be labeled as a dated release/export tied to a commit. When an image is referenced from GitHub, the record should point to the verified Drive file by ID and hash rather than duplicate the bytes.
